# 3x4 Script Lab

Локальний робочий інструмент для написання сценаріїв документальних і розслідувальних YouTube-відео
українською — у власному стилі автора, з прив'язкою тверджень до джерел.

**Потік роботи:** джерела → факти → структура → чернетка у вашому стилі → редагування → перевірки
(«Чи звучить як я?», «Факт чи інтерпретація») → експорт.

Усі дані зберігаються локально (SQLite + папка `data/`). ШІ-провайдер опційний: без нього застосунок
працює в офлайн-режимі на евристиках.

---

## Модель системи

```
Проєкт ──┬── Джерела (SourceDocument) ── Фрагменти (SourceChunk)
         │        └── Факти (ExtractedFact: твердження + сніпет + впевненість + категорія)
         ├── Структура (OutlineBlock: тип, назва, нотатки, закріплені факти)
         ├── Чернетки (ScriptDraft) ── Блоки (DraftBlock: текст з маркерами [F#], варіанти)
         ├── Історія правок (EditOperation)
         └── Профіль стилю ──> StyleProfile (глобальний) ── Корпус (StyleCorpusDocument)

LLMService ── AnthropicProvider | OpenAIProvider | OllamaProvider   (+ журнал LLMRunLog)
```

**Трасування джерел.** Кожен факт має `id`. Модель пише текст з маркерами `[F12]`. Застосунок парсить
маркери, зберігає `used_fact_ids` у блоці, автоматично виставляє факту `used_in_script`, а в панелі
«Джерела тверджень блоку» показує твердження, документ, номер фрагмента/сторінки та дослівний сніпет.
Неіснуючі id (галюцинації моделі) відкидаються.

## Можливості MVP

| Розділ | Що вміє | Без ШІ | З ШІ |
|---|---|---|---|
| **Проєкти** | створення, список, відкриття, редагування, видалення, демо-проєкт | ✅ | ✅ |
| **Дослідження** | імпорт `.md/.txt/.docx/.pdf`, нотатки, чанкінг з позиціями символів і сторінками PDF, тип джерела (авто + ручний), таблиця фактів з редагуванням, фільтрами, ⭐, ручними фактами | факти — евристикою | факти — моделлю (з дослівними сніпетами) |
| **Профіль стилю** | корпус попередніх сценаріїв → метрики, тон, «робити/уникати», n-грами, типові початки речень, переходи, вступ/фінал, рідкісні кліше, промпт і JSON | ✅ | + якісний опис голосу, приклади речень |
| **Структура** | шаблон із 9 блоків (хук → контекст → питання → механізм → актори → український кут → докази → контраргумент → висновок), додавання, ↑↓, редагування, нотатки, закріплення фактів, автопідбір фактів | ✅ | + генерація структури з дослідження |
| **Сценарій** | повна чернетка, чернетка блоку, альтернативні варіанти, додаткові вказівки, ручне редагування, підсвічування маркерів, список фактичних речень без джерела, експорт `.md` (з джерелами) / `.txt` | шаблонний каркас із фактами | ✅ |
| **Редагування** | скоротити, гостріше, конкретніше, ближче до мого стилю, прибрати кліше, документальніше, менш емоційно, перехід між блоками; «було/стало», застосування до блоку, історія | лише «кліше» та «емоційність» | ✅ усі |
| **Чи звучить як я?** | оцінка 0–100 + ярлик + діагностика з прикладами + (ШІ) переписаний варіант з повторною оцінкою | ✅ | + переписування |
| **Факт чи інтерпретація** | кожне речення → факт / інтерпретація / спекуляція / риторика; пошук підтвердження серед фактів проєкту; прапорці «надто сильно» (абсолютні слова, цифра не збігається з джерелом, факт без джерела, категоричність при слабкому джерелі) + точніше формулювання; масова заміна | ✅ | точніша класифікація |
| **Налаштування** | статус провайдерів, вибір провайдера/моделі на сесію, тест з'єднання, журнал викликів ШІ | ✅ | ✅ |

## Встановлення і запуск

Потрібно: Python **3.12** (працює й на 3.11).

```bash
# 1. клонувати
git clone <url> 3x4-script-lab && cd 3x4-script-lab

# 2. віртуальне середовище
python3.12 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate

# 3. залежності
pip install -r requirements.txt

# 4. конфігурація (необов'язково — без ключів працює офлайн-режим)
cp .env.example .env                 # і впишіть ключ потрібного провайдера

# 5. запуск
streamlit run main.py
```

Відкриється `http://localhost:8501`.

### Перші 5 хвилин

1. **Проєкти → «Завантажити демо-проєкт».** Створюються демо-профіль стилю (3 вигадані сценарії)
   і демо-проєкт (3 вигадані джерела, факти, шаблон структури).
2. **Дослідження** → перегляньте джерела й факти, відредагуйте таблицю.
3. **Структура** → змініть порядок блоків, закріпіть факти.
4. **Сценарій** → «Згенерувати повну чернетку». Праворуч від кожного блоку — джерела тверджень.
5. **Редагування** → оберіть блок/абзац → «Чи звучить як я?» і «Факт чи інтерпретація».

Для власного проєкту: створіть проєкт, завантажте джерела, у «Профіль стилю» створіть профіль і
завантажте 3–5 своїх сценаріїв (рекомендовано ≥ 3 000 слів), призначте профіль проєкту.

### Тести

```bash
pytest -q
```

Покрито: парсинг усіх 4 форматів (PDF/DOCX генеруються в тесті), чанкінг і позиції, розбиття речень,
метрики та профіль стилю, перевірка стилю, CRUD проєкту, витяг фактів (евристика і ШІ через
фейковий провайдер), структура, генерація з маркерами, варіанти, експорт, редагування, факт/інтерпретація.

## Налаштування ШІ-провайдерів

Змінні оточення (файл `.env`, див. `.env.example`):

| Змінна | Призначення | За замовчуванням |
|---|---|---|
| `DEFAULT_LLM_PROVIDER` | `anthropic` \| `openai` \| `ollama` \| `none` | `anthropic` |
| `DEFAULT_LLM_MODEL` | модель для провайдера за замовчуванням | модель провайдера |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Claude | `claude-sonnet-5` |
| `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` | OpenAI або сумісний API | `gpt-4.1-mini` |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | локальна модель | `llama3.1` |
| `LLM_TIMEOUT` | таймаут запиту, с | `180` |
| `APP_DATA_DIR` | де лежать `app.db` і `uploads/` | `./data` |

- Провайдери викликаються напряму через HTTP (`requests`), без SDK — менше залежностей.
- Провайдер і модель можна тимчасово змінити в «Налаштування» (до перезавантаження сторінки).
- Якщо ключа немає, застосунок стартує і в кожному розділі пише, яка функція потребує ШІ і що працює без нього.
- Для Ollama: `ollama pull llama3.1 && ollama serve`. Якість української у малих локальних моделей помітно нижча.

## Підтримувані файли

| Формат | Як парситься | Примітки |
|---|---|---|
| `.txt` | UTF-8 → cp1251 → koi8-u | автовизначення кодування |
| `.md` | прибирається розмітка, URL посилань зберігаються | заголовок `#` → назва документа |
| `.docx` | `python-docx`: абзаци + таблиці | стиль Title/Heading → назва |
| `.pdf` | `pypdf`: текст по сторінках, склеювання переносів | номер сторінки зберігається у фрагменті; **скани без текстового шару не підтримуються (немає OCR)** |

## Що реалізовано / що спрощено

**Реалізовано повністю (у межах MVP):** весь основний потік P1, усі функції P2, демо-дані, трасування
джерел у боковій панелі та в експорті, журнал викликів ШІ, історія правок.

**Спрощення — і чому:**

1. **Аналіз стилю — статистичний, не семантичний.** Профіль = метрики (довжини, частоти, словники маркерів).
   Він добре ловить ритм, кліше, абстрактність, щільність цифр; погано — іронію, композицію, «інтонацію».
   Якісний опис голосу додається лише через ШІ.
2. **Оцінка «Чи звучить як я?» — сума штрафів за відхилення метрик**, а не ймовірнісна модель автора.
   Число пояснюване, але не каліброване на реальних даних.
3. **Евристичний витяг фактів** обирає речення з цифрами, датами, іменами й атрибуцією. Він не розуміє зміст
   і пропускає факти без таких ознак. Результат треба переглядати.
4. **Класифікація «факт/інтерпретація» без ШІ** працює на словниках маркерів (хеджі, оцінки, абсолютні слова).
   Точність помірна; переформулювання — механічна заміна слів («всі» → «багато»).
5. **Пошук — BM25 з обрізанням слів до 6 символів** замість векторної БД і морфологічного аналізатора.
6. **Виділення тексту мишею не підтримується** (обмеження Streamlit): фрагмент обирається як «блок → абзац» або вставляється вручну.
7. **Один користувач, без авторизації**; зміна провайдера в UI діє до перезавантаження сторінки.
8. **Демо-дані вигадані** (організації, цифри, імена) — це позначено в самих файлах.

## Відомі обмеження

- PDF-скани (без текстового шару) не читаються.
- Розбиття на речення евристичне: рідкісні скорочення можуть давати помилки.
- При заміні «надто сильного» речення на пропозицію евристики маркер `[F#]` цього речення може зникнути.
- Якість генерації повністю залежить від обраної моделі; малі локальні моделі гірше пишуть українською.
- Метрики стилю нестабільні на малому корпусі (< 1 500 слів).

## Подальші покращення

- Морфологія (pymorphy3 / stanza) для точнішого стемінгу, абстрактності і n-грам.
- Локальні ембедінги для пошуку фактів і оцінки стильової близькості.
- Inline-цитування з позиціями символів у сніпеті (підсвічування в оригінальному документі).
- Порівняння версій блоку (diff) і відкат.
- OCR для сканованих PDF.
- Імпорт за URL (веб-сторінки), експорт у `.docx`.
- Калібрування оцінки стилю на відкладених сценаріях автора.
